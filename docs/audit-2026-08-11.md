### central (Python) — 재시작 완료
| 심각도 | 문제 | 수정 |
|---|---|---|
| 치명 | **RPS 카드 vs 차트 불일치 (71 vs 165)** — 카드는 (worker,instance) 라벨 시리즈 합산이라 워커 재등록 때마다 시리즈 리셋→과소집계, 차트는 라벨 없는 집계 시리즈 사용 | 전역 뷰의 카드가 차트와 동일한 `global:requests` 시리즈를 쓰도록 통일 |
| 높음 | **재시도율 355%** — 분모가 "성공 수"라 상한 없음 | `retries / (requests + retries)`로 유계(0–100%) 지표화 |
| 높음 | **차트의 죽은 워커 rate 영구 carry-forward** — 죽은 워커의 마지막 rate가 윈도우 끝까지 유지돼 과대집계 | 3×스크레이프 간격 이상 정체된 시리즈는 0으로 감쇠 |
| 치명 | **deploy 부분 실패 시 고아 컨테이너** — 5개 중 3번째 실패하면 1–2번은 기록 없이 GPU 점유 | 실패 시 이미 배포된 워커들에 stop 롤백 |
| 치명 | **deploy/stop/헬스체크 간 lost-update** — deploy가 최대 600초 전 스냅샷을 통째로 다시 저장(delete-all-reinsert) | 저장을 `_dep_lock` 하에 fresh reload 후 수행 |
| 높음 | **헬스체크 순차 실행** — 죽은 노드당 13–21초 × 40노드 = 사이클당 8–14분 (kbds 장애 때 UI가 한참 healthy로 표시된 원인) | 세마포어(16) + `asyncio.gather` 병렬화, 결과 적용은 락 하에 fresh reload로 병합 |
| 중간 | `/workers` 조회 실패 시 fail-open (죽은 인스턴스 전부 live 취급) | 마지막 성공 스냅샷 재사용 + 경고 로그 |
| 중간 | 스크레이프 실패 무음 삼킴 | 경고 로그 추가 |
| 중간 | `_metric_history` 키 무한 증가(제거된 워커 시리즈 잔존) | 보존기간 초과 시리즈 주기적 정리 |
| 중간 | 라우터 주소 하드코딩 | `ROUTER_METRICS_URL` / `ROUTER_WORKERS_URL` / `P2C_ROUTER_URL` 환경변수화 |
| 낮음 | 전역 뷰 `target_urls`가 latency 시리즈 있는 워커만 포함 | processed 키 합집합으로 확장 |

### worker (Python)
| 심각도 | 문제 | 수정 |
|---|---|---|
| 높음 | **deploy가 이벤트루프 블록(수 분)** → 하트비트 정지 → central이 워커를 오프라인 오판 | `asyncio.to_thread`로 deploy/stop 오프로드 |

| 중간 | `__pycache__`/*.pyc git 추적 | `.gitignore` 추가 + `git rm --cached` |

## ⚠️ 남은 권고사항 (결정 필요 — 코드 미변경)

### 보안 (긴급)
1. **worker `/api/internal/*` 무인증 + 공인 IP 바인딩 + docker.sock 마운트** = 원격 루트 수준 RCE 경로. 공유 시크릿(Bearer) 의존성 추가 + tailnet 전용 바인딩 권장. central도 같은 토큰을 보내도록 양쪽 동시 배포 필요해서 이번엔 보류.
2. **시크릿 로테이션**: `bislaprom3#`(JS로 이미 공개됨, LiteLLM 마스터키와 재사용), `.env.central`의 Tailscale authkey. 즉시 로테이션 권장.
3. HF 토큰이 렌더링된 compose 파일(644)과 `docker run -e` argv로 노출. env_file/secret 방식으로 전환 권장.
4. `ipc: host`(vllm_node.j2) — 컨테이너 격리 약화. TP 요구가 없다면 `ipc: shareable` 검토.
5. CSP 부재 + CDN 스크립트 SRI 없음(base.html).

### 아키텍처
6. **`--max-concurrent-requests`는 실제로 동시성 제한이 아님** — TokenBucket이 초당 refill(기본 refill=capacity/초)이라 사실상 유량 제한. 진짜 동시성 캡이 필요하면 세마포어 의미론으로 재구현 필요. (이번에 토큰 수명은 body에 묶어서, refill을 낮게 설정하면 의도대로 동작하는 기반은 마련됨)
7. **Prometheus instance 라벨(ULID) 무한 카디널리티** — 워커 재등록마다 새 시리즈. `instance` 라벨 제거 또는 워커 제거 시 시리즈 정리 필요. central 파서/프론트도 같이 바꿔야 해서 보류.
8. 재시도 증폭: `max_retries=5` 기본 + 업스트림 에러 전부 500 변환. 과부하 시 5배 증폭 가능. `--disable-retries` 또는 max 2 권장.
9. `restart: unless-stopped` + 상태파일 유실 조합 → 리부트 후 유령 컨테이너. worker 기동 시 `docker ps` ↔ 상태파일 reconcile 권장.
10. central의 sqlite 호출이 전부 이벤트루프에서 동기 실행(폴링 핫패스 포함). `asyncio.to_thread` 또는 캐싱 권장.
11. 하드코딩 호스트 경로(`/home/uiyunkim/...`)가 worker compose에 잔존 — 다른 머신 배포 시 깨짐.
12. vLLM 템플릿에 `--max-num-seqs` 미설정(기본 256) — gpu_util 0.95와 조합 시 KV OOM 크래시루프 위험.

### 배포 절차 메모
- **worker 변경분은 각 GPU 머신의 worker 컨테이너를 재배포해야 반영됨** (이 저장소 수정만으로는 원격 워커에 미적용).
- 라우터/central은 이 호스트에서 반영 완료.
